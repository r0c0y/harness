# Changelog drafting

1. Read the actual diff and tests; do not infer features from commit titles alone.
2. Group changes by user impact and separate fixes, additions, and breaking changes.
3. Describe outcomes in clear language, with migration notes only where needed.
4. Exclude internal churn and claims unsupported by evidence.
5. Follow the repository's existing format and do not edit a release file unless requested.
