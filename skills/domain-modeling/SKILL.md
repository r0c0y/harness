# Domain modeling

1. Collect the terms already used in requests, UI labels, APIs, and tests.
2. Separate entities, values, events, states, and actions; note where names are ambiguous.
3. State important invariants and legal state transitions in plain language.
4. Use concrete examples to test whether the model explains real behavior.
5. Propose canonical terms without renaming code or persisted data unless asked.
