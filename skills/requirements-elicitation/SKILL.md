# Requirements elicitation

1. Read the request, repo instructions, and existing behavior first.
2. Extract actors, inputs, outputs, permissions, failure cases, and acceptance conditions.
3. Resolve discoverable facts from the repository instead of asking the user.
4. Ask only questions whose answers would materially change the implementation or risk.
5. Record confirmed requirements separately from assumptions and non-goals.

Keep clarification proportional to the change. A clear request does not need an interview.
