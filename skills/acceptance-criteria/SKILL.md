# Acceptance criteria

1. Express each criterion as an observable outcome, not an internal implementation detail.
2. Cover the normal path, important boundary conditions, and expected failure behavior.
3. Reuse the project's vocabulary and existing test conventions.
4. Keep each criterion independently verifiable and avoid duplicating the same rule.
5. Map each criterion to a test or other evidence before declaring completion.

Do not add requirements that the user did not request; label useful ideas as optional follow-ups.
