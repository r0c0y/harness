# Technical design

1. Summarize the current behavior and the desired behavior.
2. Describe the smallest affected modules and their responsibilities.
3. Include data flow, error paths, security boundaries, and compatibility concerns.
4. List alternatives rejected and why, without turning the design into a speculative roadmap.
5. Close with implementation steps and concrete verification evidence.
