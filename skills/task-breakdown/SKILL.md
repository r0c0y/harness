# Task breakdown

1. Start with the outcome and its end-to-end acceptance condition.
2. Split by user-visible behavior or stable vertical seam, not by arbitrary file type.
3. Make each slice small, testable, and independently useful where possible.
4. Record dependencies and risks that make sequencing necessary.
5. Avoid creating issue-tracker work unless the user requested that external change.
